# Controlled Circulation Policy

## Executive Summary

FUZE uses a **Controlled Circulation Policy** to govern how FUZE token allocations move from vaults, reserves, vesting schedules, incentive programs, migration systems, participation windows, and operational allocations into active circulation.

The policy protects FUZE from treating every allocation as automatic liquid supply. FUZE separates work compensation, product usage, ecosystem participation, and market-structure support into different systems.

**Stablecoins pay for work. FUZE tokens align long-term participation. Platform Credits are for product usage. FUZE token is for ecosystem participation.**

Controlled circulation supports FUZE as a transparency-first AI SaaS platform by connecting token release to allocation purpose, product readiness, contributor alignment, community eligibility, vault rules, market-structure policy, governance controls, and public reporting.

FUZE does not present controlled circulation as price support, liquidity protection, listing assurance, return protection, or market outcome control. It is a governance, release, vault-control, and reporting policy for responsible token circulation.

This paper defines FUZE’s controlled circulation model, release categories, allocation relationships, vault relationship, product context, reporting direction, and risk safeguards.

## 1. FUZE Position

FUZE uses Controlled Circulation Policy as the public policy for token movement from allocation vaults into active circulation.

FUZE position:

**Controlled circulation means FUZE token movement is governed by allocation purpose, product readiness, eligibility, vesting, lockups, treasury policy, market-structure policy, governance controls, and public reporting direction.**

The Controlled Circulation Policy follows the FUZE tokenomics principle:

**Purpose-specific allocation. Vault-based control. Controlled circulation. Product-first utility. Long-term ecosystem alignment.**

Controlled circulation exists because FUZE uses a fixed **500,000,000 FUZE** total supply across purpose-specific allocations. Each allocation category has a different public role and a different release logic. Community Participation does not behave like Team Allocation. BOARD / Surfboard Migration does not behave like Liquidity & Market Operations. Treasury Reserve does not behave like Holder Incentives. Transparency / Stability Reserve does not behave like normal circulating inventory.

FUZE uses controlled circulation to make those differences clear.

## 3. Public Model

### 3.1 Controlled Circulation Definition

Controlled circulation means that FUZE tokens enter active circulation only through a defined purpose, approved release logic, and relevant policy controls.

| Control Area | Public Meaning |
|---|---|
| Allocation purpose | Each token category has a defined reason to exist |
| Vault control | Tokens remain in category-specific vaults or controlled accounts before release |
| Eligibility | Some releases require user, contributor, holder, partner, or legacy-holder eligibility |
| Vesting / lockup | Some releases occur over time rather than immediately |
| Product readiness | Some releases depend on product, utility, or platform readiness |
| Compliance readiness | Some releases depend on legal, jurisdiction, compliance, and policy review |
| Governance control | Some releases require approval, timelock, multisig, policy review, or reporting |
| Public reporting | Releases can be shown through public-safe dashboards, updates, or documents where appropriate |
| Risk boundary | Releases do not create token price, liquidity, listing, payout, or return promises |

Controlled circulation is a public trust policy.

### 3.3 Release Type Framework

FUZE uses release types to make token movement easier to understand.

| Release Type | Public Meaning | Best-Fit Categories |
|---|---|---|
| Permanent Lock / Non-Circulating Hold | Tokens remain locked or held and do not enter circulation unless final policy changes under governance controls | Foundation Reserve, Transparency / Stability Reserve where applicable |
| Claim-Based Release | Tokens become claimable by eligible parties under defined rules | BOARD / Surfboard Migration, selected Community Participation programs |
| Vesting Release | Tokens release over time to support long-term alignment | Team Allocation, Advisors / Strategic Contributors |
| Earned Release | Tokens release after participation, contribution, campaign completion, product usage, or eligibility rules | Holder Incentives, Community Participation Allocation |
| Milestone Release | Tokens release when partner, ecosystem, integration, or contribution milestones are approved | Ecosystem Growth & Partnerships |
| Strategic Reserve Deployment | Tokens move only for approved platform, treasury, or strategic purposes | Treasury Reserve, Foundation Reserve |
| Controlled Operational Deployment | Tokens move for market-structure or operational purposes under policy controls | Liquidity & Market Operations |
| Exceptional Reserve Use | Tokens move only for trust, transparency, or stability needs under governance controls | Transparency / Stability Reserve |

This framework helps public readers understand that token movement is not one uniform unlock schedule.

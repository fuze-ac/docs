# FUZE Public Language Dictionary

## Executive Summary

FUZE Public Language Dictionary defines approved FUZE public language, avoided phrases, safer replacement wording, product-specific boundaries, token-specific boundaries, investor-safe language, community-safe language, and documentation review standards.

FUZE uses one token only: FUZE token.

FUZE token is the single ecosystem token of FUZE. It supports product-connected utility, ecosystem participation, platform alignment, governance direction where applicable, and wallet-based participation ability.

Public language matters because FUZE combines practical AI SaaS products, Platform Credits, stablecoin rails, wallet-level transparency, public reporting, token utility, private strategic fundraising, product revenue readiness, ZAGA game mechanics, QTB market interpretation, AIMM liquidity operations support, and possible future wallet-based participation ability.

These topics must be explained clearly without creating unsafe expectations.

FUZE public language avoids claims that sound like guaranteed payout, guaranteed income, dividend, passive income, fixed yield, price support, guaranteed listing, guaranteed liquidity, guaranteed exit, guaranteed trading profit, guaranteed game earnings, guaranteed AI accuracy, or guaranteed investment return.

Platform Credits are product usage credits and are separate from FUZE token.

Stablecoins are payment, settlement, treasury, and compensation rails.

Wallet-based participation ability is not a second token, not automatic for every wallet, and not active as a guaranteed public payout right.

FUZE uses wallet-level transparency without public identity exposure.

This dictionary helps FUZE writers, contributors, community members, investors, partners, product teams, and documentation reviewers use consistent public wording.

## 2. FUZE Public Language Position

FUZE’s public language position is:

FUZE communicates in product-first, transparency-first, compliance-aware, investor-readable, and community-readable language.

The public language system has eight core rules.

| Rule | Meaning |
|---|---|
| Product-first | Explain real products before token expectations. |
| One-token clarity | FUZE uses one token only: FUZE token. |
| Credit separation | Platform Credits are product usage credits, not token or investment rights. |
| Stablecoin separation | Stablecoins are payment, settlement, treasury, and compensation rails. |
| Wallet-based privacy | Public records can show wallets without exposing personal identity publicly by default. |
| Activation-gated participation | Wallet-based participation ability is conditional and not active as a guaranteed payout right. |
| No market promise | FUZE avoids price, listing, liquidity, trading volume, exit, and market support promises. |
| No outcome guarantee | FUZE avoids guaranteed product, revenue, AI, game, community, or investment outcomes. |

The dictionary helps FUZE keep public communication clear and safe.

- FUZE uses two tokens.
- FUZE token and FPPU are both public tokens.
- FPPU holders receive profit.
- FUZE token holders automatically receive distribution.
- One token means every holder gets payout.

Replacement wording:

| Avoid | Use Instead |
|---|---|
| FPPU | wallet-based participation ability |
| Profit Participation Unit | wallet-based participation framework |
| FPPU holder | eligible FUZE-holding wallet |
| FPPU distribution | approved participation distribution |
| FPPU claim | eligible-wallet claim |
| FPPU contract | participation claim module or distribution module |

Boundary:

Do not use FPPU as public-facing language. The term may appear only in private/internal papers if needed to explain legacy terminology.

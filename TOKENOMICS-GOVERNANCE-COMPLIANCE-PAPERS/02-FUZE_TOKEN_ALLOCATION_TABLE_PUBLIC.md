# FUZE Token Allocation Table

## Executive Summary

FUZE Token Allocation Table defines the fixed token supply and final public allocation model for FUZE token.

FUZE uses one ecosystem token only: FUZE token.

FUZE uses a fixed total supply of **500,000,000 FUZE** organized across ten purpose-specific allocation categories. The allocation model supports FUZE as a transparency-first AI SaaS platform, not a token-first project.

The allocation model follows five core tokenomics principles:

**Purpose-specific allocation. Vault-based control. Controlled circulation. Product-first utility. Long-term ecosystem alignment.**

FUZE separates:

| System | Public Role |
|---|---|
| FUZE token | Ecosystem participation, alignment, governance direction where applicable, product-connected utility, and wallet-based participation ability where activated |
| Platform Credits | Product usage credits for FUZE products and services |
| Stablecoins | Payment, settlement, treasury, and operational compensation rails |

The allocation table gives public readers a clear view of how the full FUZE token supply is structured. It defines the role of community participation, legacy-holder migration continuity, team and contributor alignment, treasury discipline, foundation stewardship, holder incentives, ecosystem growth, liquidity-related operations, advisor alignment, and transparency reserves.

This paper is not a token sale document, investment recommendation, public solicitation, listing plan, liquidity assurance, price forecast, payout policy, legal opinion, tax opinion, accounting policy, or financial-return promise.

## 5. How the System Works

### 5.1 Vault-Based Control Direction

FUZE uses vault-based control to keep allocation categories separated by purpose.

| Allocation Category | Control Direction |
|---|---|
| Community Participation Allocation | Community participation contract or vault structure |
| BOARD / Surfboard Migration | Migration contract or eligibility vault |
| Team Allocation | Team vesting vault |
| Foundation Reserve | Foundation reserve vault |
| Treasury Reserve | Treasury reserve vault |
| Holder Incentives | Holder incentives vault |
| Ecosystem Growth & Partnerships | Ecosystem partnership vault |
| Liquidity & Market Operations | Liquidity operations vault |
| Advisors / Strategic Contributors | Advisor or strategic contributor vesting vault |
| Transparency / Stability Reserve | Transparency / stability vault |

Vault-based control supports transparency, reduces category misuse, and gives public readers a clearer view of what each allocation category is designed to do.

A vault balance is not automatically circulating supply, approved distributable value, payout supply, price support, liquidity guarantee, or public treasury access.

### 5.2 Controlled Circulation Relationship

The allocation table connects directly to FUZE’s Controlled Circulation Policy.

Controlled circulation means token movement is governed by purpose, timing, policy, legal readiness, product readiness, market context, governance controls, and public reporting direction.

| Release Category | Best-Fit Allocation Areas |
|---|---|
| Community participation release | Community Participation Allocation |
| Migration claim release | BOARD / Surfboard Migration |
| Vesting release | Team Allocation; Advisors / Strategic Contributors |
| Strategic reserve release | Treasury Reserve; Foundation Reserve |
| Earned campaign release | Holder Incentives |
| Partnership milestone release | Ecosystem Growth & Partnerships |
| Controlled operational deployment | Liquidity & Market Operations |
| Exceptional reserve use | Transparency / Stability Reserve |

This model keeps allocation categories tied to defined use cases rather than uncontrolled circulation.

Controlled circulation does not mean price control, price support, guaranteed liquidity, guaranteed listing, or guaranteed exit.
